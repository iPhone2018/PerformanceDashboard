# Valmet 操作与报警事件看板

Flask + ECharts 的 Web 看板，直接扫描 `data/` 目录下的 Pareto Excel（DCS 导出的原始版式），
按小时 / 按天统计 Operation 与 Alarm 事件，两类事件全程分开统计。**不使用任何模拟数据**。

## 运行

```bash
./venv/bin/pip install -r requirements.txt
./venv/bin/python app.py
# 浏览器打开 http://127.0.0.1:5055/
```

端口可用环境变量覆盖：`PORT=8080 ./venv/bin/python app.py`

## 看板内容

| 区域 | 内容 |
|------|------|
| 近 24 小时趋势 | 操作 / 报警两条折线，24 个整点，带圆点标记；**点击任意圆点直接下载该小时的原始 Excel** |
| 近 7 天趋势 | 操作 / 报警两条折线，7 天，带圆点标记；**点击任意圆点直接下载该天的原始 Excel** |
| 近 24 小时 TOP10 Tag · 操作 | 横向条形图，Tag 名在左，柱端标注 `次数 + 占该类事件百分比` |
| 近 24 小时 TOP10 Tag · 报警 | 同上（报警用橙色，与折线图配色一致） |
| 近 7 天 TOP10 Tag · 操作 | 按 Tag 7 天合计排序 |
| 近 7 天 TOP10 Tag · 报警 | 同上 |

- 四张排行图 2×2 排列，操作/报警各自成图、互不混算。
- 点击任意柱子弹出该 Tag 的名称 / 描述 / 类型 / 次数 / 占比。
- 每张排行图下方有按钮，下载**该时段该类事件的全部原始明细**（不只是 TOP10）。
- 深浅色主题、每 5 分钟自动刷新，顶栏显示数据截止时间与文件数量。

> 排行图为什么用横向条形图：2×2 排布下每张图只有半屏宽，10 个 Tag 名再加
> 「名称+次数+占比」标签在竖向柱状图上必然重叠（ECharts 会隐藏部分标签或互相压字）。
> 横向排布后 Tag 名完整显示在左侧、数值标在柱端，任何窗口宽度下都不会重叠。

## 统计口径

- **基准时间取机器当前时间，不取数据里最新的文件**：这样采集断掉的时段会老老实实
  缺在图上，而不是被"挪出"窗口之后看起来一切正常。顶栏「数据截止」写的是数据里
  最新的一格；数据比当前时间旧时，后面会追一句「数据比当前时间旧 N 小时」。
- 近 24 小时 → 取 `data/hourly`，从**最后一个走完的整点**往前 24 个整点
  （17:13 打开 → 末点到 16:00）。正在走的这一小时只统计了十几分钟，画上去最后一个点
  必然偏低，所以不进窗口（采集端照常采，只是不参与统计）；页面副标题会写明
  「末点 … （最后一个走完的整点）」。末点那个小时要是还没采到，就断线并计入缺失。
- 近 7 天 → 取 `data/daily`，从**昨天**往前 7 天，同理（当天那份日报只走了半天）。
  **两个窗口都到"最后一个走完的时段"为止**，口径一致。
- **操作与报警分开统计**：TOP10 的占比分母是同时段**同类事件**总数
  （操作图的分母只算操作事件，报警图只算报警事件），图上标注会写明。
- 缺数据的时段在折线图上留空（不是 0），避免把"没采集到"画成"没有事件"。

## 数据缺失时怎么表现

看板把三种情况严格分开，**不会把"没采到"画成"没有事件"**：

| 情况 | 折线 | 排行图 / 总量 | 页面提示 |
|------|------|--------------|----------|
| 某小时/某天**没有 Excel 文件** | 该点为 `null`，折线**断开**，并在图上画出灰色缺口带 | 不计入总量、不计入 TOP10 | 顶部红色横幅 + 图下方红字，列出缺哪几个时段 |
| 文件存在但**只有一类**（比如只有 Operation，Alarm 文件没导出） | 该类断线，另一类照常有数 | 只统计实际有的那一类 | 同上 |
| 文件存在但**里面 0 条明细** | 画成真实的 `0`（不是断线） | 计 0，不影响总量 | 单独提示「N 个文件里没有明细记录」 |
| 某个窗口**一个文件都没有** | 折线整段断开，图上显示「暂无数据」 | 总量 0、TOP10 为空 | 区分两种成因：目录里没文件 →「data/hourly 下没有任何符合命名规范的小时文件」；文件都在窗口之外（采集停过 / 看的是历史数据）→「这 24 个整点都没有数据文件（data/hourly 里最新的到 …）」 |
| `hourly` 和 `daily` **都为空** | 页面显示中文错误提示 | — | 接口返回 `ok=false` 并说明数据目录 |

- 每张图的副标题都带 `数据覆盖 21/24 个整点` 这样的覆盖率，一眼能看出这段统计完整不完整。
- 缺文件的小时点不出圆点，即使直接请求接口也会返回 404（而不是给一个空文件）。
- 空文件那个小时仍可下载——文件确实存在，只是没有事件记录。
- 单文件坏掉（不是合法 xlsx、表头找不到）只跳过该文件并在横幅里列出，不影响其它数据。

## 数据目录约定

```
data/
  hourly/
    Alarm_YYYYMMDD_HHMM.xls        # 某一小时的 Alarm Pareto 明细
    Operation_YYYYMMDD_HHMM.xls    # 某一小时的 Operation Pareto 明细
  daily/
    Alarm_YYYYMMDD.xls             # 某一天的 Alarm Pareto 明细
    Operation_YYYYMMDD.xls         # 某一天的 Operation Pareto 明细
```

扩展名 `.xls` 和 `.xlsx` 都认：DCS 的 `ExcelPreview.aspx` 导出的是老式 `.xls`（OLE2），
而看板的下载接口产出的是 `.xlsx`。同一时段两种格式同时存在会被**重复计入**，别混放。

文件版式就是 DCS 导出的原始 Pareto Report —— 顶部几行报表头（`Start:` / `End:` /
`Row limit` / `Rows retrieved` / `Bar limit`），下面是 `Type | Tag | Description | Count`
明细表，末尾可能还跟着 `Filter criteria:` 页脚。真实 `.xls` 里标签和值分处两格
（`r2c1="Start:"`、`r2c2="2026/9/20 8:00:00"`），数据落在第 1/3/5/7 列。

解析器按表头定位列、从报表头读取 Start 时间，两类版式（标签与值同格 / 分格）都认，
因此列顺序、报表头行数有出入也能读。把新导出的 Excel 按上面的命名规则丢进对应目录，
刷新页面即可，无需改代码。

> 时段归属优先取文件里的 `Start`，取不到才退回文件名。文件名不合规范的文件会被跳过，
> 并在页面上以提示条列出，不会影响其它数据。

## 接口

| 接口 | 说明 |
|------|------|
| `GET /api/data` | 看板聚合数据（两条趋势 + 四张排行图），单次请求拿全 |
| `GET /api/download/hour?key=YYYYMMDDHH` | 该小时的原始明细（操作 + 报警，两张 sheet） |
| `GET /api/download/day?key=YYYY-MM-DD` | 该天的原始明细（操作 + 报警，两张 sheet） |
| `GET /api/download/window?range=24h\|7d&type=Operation\|Alarm` | 该时段该类事件的全部原始明细 |

下载文件的 `Tag汇总` 表与页面柱状图**逐字一致**（含占比小数位），可直接核对。
`全部原始明细` 表保留源文件的 `Type / Tag / Description / Count` 列；跨时段下载会多一列 `时间`。

## 自测

```bash
./venv/bin/python data_generator.py     # 演示数据得是"现在"的：窗口按当前时间定
./venv/bin/python selftest.py
```

自测脚本自己起服务（自动挑空闲端口，并在启动后校验读的确实是目标数据目录，避免端口撞车
连到别的实例上），**不调用 app.py 里的任何函数**，直接用 pandas 把 Excel 重算一遍，再逐项
比对接口返回值、三个下载接口产出的 Excel 内容以及页面 HTML；最后再另起一个服务，喂一份
**造出来的残缺数据**（缺 4 个整点含当前整点、只有一类文件、空文件、缺 2 天、目录全空），
验证上表中的每种表现。共 150+ 项断言，含 400/404 等异常分支。

> 窗口基准是机器当前时间，所以自测依赖 `data/` 里的演示数据覆盖当前那个 24 小时 /
> 7 天窗口 —— 放旧了第一段就会红（脚本会直说是数据旧了，让先跑 `data_generator.py`）。
